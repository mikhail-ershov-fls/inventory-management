Architecture overview

Factory Inventory Management System

A two-tier demo application: a Vue 3 single-page app talks to a stateless FastAPI service over JSON. There is no database. All data is loaded from JSON files into memory when the server starts, and filtering is done with Python list comprehensions on every request.

Data flow: changing a filter

This is the main interaction pattern. Picking a warehouse in the filter bar reloads every panel on the current view.

  1. components/FilterBar.vue → composables/useFilters.js

    The user picks a value. The <select> is bound to a module-level ref (selectedLocation). The refs are defined outside the composable function, so every component shares the same filter state.

  2. views/Dashboard.vue (and the other views)

    The view watches the filter refs and calls getCurrentFilters(), which maps the UI names to API names (selectedLocation becomes warehouse, selectedPeriod becomes month).

  3. api.js

    The API client leaves out any filter set to 'all', builds a query string, and the view runs its requests in parallel with Promise.all.

    GET /api/dashboard/summary?warehouse=Tokyo&month=Q2-2025
GET /api/orders?warehouse=Tokyo&month=Q2-2025
GET /api/inventory?warehouse=Tokyo
GET /api/backlog
  4. server/main.py

    FastAPI binds the query params to Optional[str] arguments. apply_filters() does exact warehouse matching and case-insensitive category and status matching. filter_by_month() expands Q2-2025 into three YYYY-MM prefixes and substring-matches them against order_date.

  5. server/mock_data.py (memory)

    The filters run over the lists loaded at startup. There is no I/O on the request path. Summary endpoints add up inventory value, low-stock counts and pending orders from the filtered lists.

  6. Pydantic → JSON → Vue refs → computed

    The response is validated against response_model and returned as JSON. The view stores raw arrays in refs, and charts, KPIs and tables are computed from them. Currency is formatted per locale (USD, or JPY at a fixed rate of ×150).

Filter dimensions

  • Warehouse: San Francisco, London, Tokyo
  • Category: Circuit Boards, Sensors, Actuators, Controllers, Power Supplies
  • Order status: Delivered, Shipped, Processing, Backordered
  • Time period: 2025-01 to 2025-12, or Q1-2025 to Q4-2025 (orders only)

Business rules in code

  • Low stock: quantity_on_hand <= reorder_point
  • Pending orders: status in Processing or Backordered
  • Fulfilment rate: delivered / total orders per quarter
  • Revenue goals: $800K per month, $9.6M year to date

Gaps & observations

Worth knowing before you change anything.

Client calls endpoints that do not exist

api.js defines task CRUD (/api/tasks) and purchase-order calls (/api/purchase-orders), but main.py has no such routes, so they return 404. The tasks modal falls back to the mock tasks hard-coded in useAuth.js.

Backlog view is not routed

views/Backlog.vue exists but is not registered in the router in main.js. Backlog data is only shown on the Dashboard.

Inconsistent API access

Reports.vue imports axios and hard-codes http://localhost:8001 rather than going through api.js. The base URL is hard-coded in both places, with no environment configuration.

Several endpoints ignore filters

Demand, backlog, spending and reports always return the full dataset. Inventory has no time dimension, so the period filter has no effect on it. total_backlog_items in the dashboard summary is never filtered.

Demo-grade by design

There is no authentication (the user is mocked), CORS allows *, there is no persistence, and the time filters assume 2025 data (QUARTER_MAP is hard-coded).
